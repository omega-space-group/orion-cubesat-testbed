◆ HAL_TIM_PeriodElapsedCallback()

void HAL_TIM_PeriodElapsedCallback ( TIM_HandleTypeDef * htim)

TIM6 callback function.

Whenever TIM6 overflows, the callback increments the global variable "uwTick" used as application time base for Cortex-M7.

Warning
To prevent interrupt priority inversion and deadlocks, we separate the RTOS timebase from the HAL timebase using TIM6 as the HAL timebase and SysTick for RTOS
  1. SysTick is dedicated exclusively to the RTOS and is assigned the LOWEST priority so it doesn't block time-critical ISRs.
  2. A dedicated hardware timer (TIM6) is used for the HAL timebase (HAL_Delay) and is assigned a HIGH priority. This ensures HAL timeouts can safely execute even when called from within peripheral interrupts.

Using SysTick for both would cause a deadlock if a HAL function with a timeout were ever called from a high-priority interrupt handler.

◆ main()

int main ( void )

Peripheral and RTOS Initialization.

  1. Every peripheral is initialized.
  2. RTOS Kernel is initialized.
  3. MX_FREERTOS_Init() is called to initialize the Root Task
  4. The kernel is started. From now on there is no serial execution and the scheduler has control.
    Note
    1. There is a 5 sec delay before initializing the OS to make sure all peripherals are brought up fully.
    2. TIM7 is used to keep track of FreeRTOS Statistics (FreeRTOS Task List, Timers etc) for debugging purposes.
    3. Look into Flash and Debug Manual for more info on how Cortex-M7 handles flashing.
    Warning
    Control should never reach main's inifinite loop because that would mean the RTOS has failed.
